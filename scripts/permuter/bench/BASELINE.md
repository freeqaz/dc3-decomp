## Flag A/B (off vs on, isolated fresh cache per (fn,arm))

Harness: `scripts/permuter/bench/flag_ab.py`. Gate for default-on: zero
win-rate regression + zero new crashes.

| Flag | set | OFF wins | ON wins | OFF vars | ON vars | crashes | Verdict |
|------|-----|----------|---------|----------|---------|---------|---------|
| `PERMUTER_HARD_FILTERS` (+adaptive) | 10 mid/low | 3 | 3 | 336 | 336 | 0 | **NO_EFFECT** (never fires) |
| `PERMUTER_PREDICTOR` (budget=15) | 10 mid/low | 3 | 3 | 356 | **245** | 0 | **SAFE** (−31% compiles) |
| `PERMUTER_C1_SOURCE_DIFF` off vs both (+chain+m2c) | 5 mid | 3 | 3 | 197 | 197 | 0 | **NO_EFFECT** (no regression) |

**HARD_FILTERS — NO_EFFECT / safe but inert on DC3.** Byte-identical OFF vs ON
on all 10 functions (same variants, same wins, same rounds-to-win). The hard
drop only fires when `TargetFacts.hard_suppress_patterns()` clears a 0.85
confidence bar (target_facts.py:91); the DC3 atlas/facts here never reach it,
so no pattern is ever hard-dropped. Safe to default-on (cannot regress) but
provides no measured benefit on this set.

**PREDICTOR (budget) — SAFE, the real win.** With `PERMUTER_PREDICTOR=1` and
`PERMUTER_PREDICTOR_BUDGET=15` (below the per-round variant count so culling
actually fires), the predictor cut total compiles 356→245 (**−31%**) while
preserving all 3 wins and every rounds-to-win. The winning patterns are
high-priority phase-1 independents, so they sit at the front of the queue and
survive the bottom-fraction cull. Per-function: HamDirector 36→18 (win kept),
ArcDetector 35→18 (win kept), WavReader 19→15 (win kept), plus 4 non-winners
trimmed ~30-44%. Note: with a thin/fresh history the model ties all scores, so
the cull degrades to "keep the first `keep` in generation order" — the safety
result is therefore about *queue ordering*, not model quality. Recommend
default-on **only paired with a sane budget** (the flag alone defaults
budget=max_variants → no-op).

**C1 source-diff (`off` vs `both`) — NO_EFFECT, no regression.** Run with
`--chain --m2c` so the signal is *actually exercised* (m2c loaded 12×, beam
built chains 14× across the 5 fns — confirmed in the log). This matters
because the *prior* C1 validation (`c1_source_diff_ab.py`) called `hill_climb`
with neither `m2c=True` nor `chain=True`, so `_compute_source_diff_score`
(beam_search.py:403) early-returned `None` and the prior "validated" result
was a trivial no-op against an inert codepath. Even with the path live, off
vs both produced byte-identical results on all 5 functions (3 wins each, 197
variants each, mean_rtw 1.0). The signal only reorders beam-chain exploration;
within the beam budget the same winners are still reached. Safe to keep
default-on (`both`) but provides no measured win/speed benefit on DC3.

## Optimization findings (ranked, actionable)

1. **27% of compiles are wasted on uncompilable variants.** 225 / 826 bench
   variants returned `BUILD FAILED` (~115 s of compile time at 511 ms/compile).
   `variable_extraction` (`varext`) alone caused **74** of them — it extracts
   call expressions into `auto _tmp` locals
   (`scripts/permuter/patterns/variable_extraction.py`) in contexts where the
   result won't compile (macro args like `MILO_ASSERT`, side-effect-ordered
   sub-expressions, scopes where `auto` deduction fails). Other repeat
   offenders: `signed_unsigned` (32), `symbol_str_compare` (17),
   `declaration_movement` (16), `argument_swap` (13). A pre-queue syntax probe
   (tree-sitter parse of the edited region) or tightening the extraction-site
   filter would reclaim the largest single block of throughput. NB:
   `variable_extraction` has an 89% *win* rate when it does build — fix the
   generation, don't disable it.

2. **`PERMUTER_PREDICTOR` + a real budget is the cheapest 31% compile cut.**
   See A/B above. The flag is inert without `PERMUTER_PREDICTOR_BUDGET` <
   max_variants. The win is purely from culling the back (compose/chain) of the
   queue, which the winning phase-1 patterns never occupy.

3. **A2/A4 (compile/objdiff daemon) is not worth building.** Spawn is <0.4% of
   subprocess time (compile 0.84 ms spawn vs 511 ms run; objdiff 1.02 ms vs
   268 ms). All cost is real work; a daemon saves nothing.

4. **BSF tracing is silently disabled in worktrees without the 32-bit debug
   wibo** (`/tmp/claude/wibo/build/debug/wibo`). `declaration_reorder`'s
   BSF-guided GPR-swap synthesis (`patterns/declaration_reorder.py:685`) falls
   back to non-BSF swaps on every diagnosis. Fails fast (a `.exists()` check,
   not a spawn) so no throughput cost, but it degrades diagnosis quality / may
   miss reg-swap wins. Build the 32-bit debug wibo in sweep worktrees.

5. **Rounds 2-3 re-generate round-1 variants** (caught by the score cache, not
   source-dedup which is per-generate-call). E.g. `cache: persistent=21,
   builds=1` on later rounds — compiles are saved but generation work is
   repeated. Minor; a cross-round generated-source set would trim Python
   overhead (the 11% python-overhead bucket).

## How to reproduce the A/Bs

```bash
# HARD_FILTERS (needs --adaptive so round_hints exists)
PYTHONHASHSEED=0 ./venv/bin/python -m scripts.permuter.bench.flag_ab \
    --bands mid,low --limit 10 --adaptive \
    --on PERMUTER_HARD_FILTERS=1 --label hard_filters
# PREDICTOR (budget below variant count so culling fires)
PYTHONHASHSEED=0 ./venv/bin/python -m scripts.permuter.bench.flag_ab \
    --bands mid,low --limit 10 \
    --on PERMUTER_PREDICTOR=1 --on PERMUTER_PREDICTOR_BUDGET=15 --label predictor
# C1 (must enable --chain --m2c or the source-diff path never runs)
PYTHONHASHSEED=0 ./venv/bin/python -m scripts.permuter.bench.flag_ab \
    --only HamDirector::OnFileLoaded,ArcDetector::GetSwipeAmount,WavReader::Poll \
    --chain --m2c --on PERMUTER_C1_SOURCE_DIFF=both \
    --off PERMUTER_C1_SOURCE_DIFF=off --label c1_sourcediff
```
