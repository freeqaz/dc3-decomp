# Controller-mode wake + idle timeout (DtaFlowControllerMode* tests).
#
# On the 360 a pad press outside controller mode only ENTERS controller mode
# (ShellInput::OnMsg(ButtonDownMsg)) and controller mode exits after the
# helpbar's controller_mode_timeout without pad input (ShellInput::Poll).
# `wake` is "the player presses the wake button" (L3 unless
# MILO_INPUT_WAKE_BUTTON): a no-op while the game is in controller mode, a
# press otherwise.  See docs/debugging/native.md "Controller mode policy".
#
# Run under DC3_CONTROLLER_MODE=faithful DC3_CONTROLLER_MODE_TIMEOUT_MS=750
# (the test does), main_screen idles for ~1900 frames with a pair of wakes,
# 10 frames apart, every 120 frames: each timeout exit must be followed by a
# wake that presses and re-enters, and the second wake of a pair whose first
# one pressed lands inside controller mode and must be a no-op (10 frames is
# far below the 750 ms timeout at any frame rate the engine reaches, which
# the 120-frame spacing is not).  The closing wake+confirm pairs must reach
# choose_mode_screen whatever state the cycle is in.  Under the default
# DC3_CONTROLLER_MODE=forced every wake is a no-op.
