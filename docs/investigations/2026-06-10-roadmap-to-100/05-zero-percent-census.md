# 05 — Zero-Percent Census: Classifying the "5.44 MB Half of the Codebase"

## Question
The scout reported 19,626 functions at `current_percent=0` summing 5,438,800 bytes — "half the codebase by bytes." Until this bucket is classified, "done at 100%" is meaningless. Classify every row into MSVC EH funclets / never-decompiled whole units / stubbed-but-present / merged-ICF / excluded / data-or-compiler-generated / genuinely-authorable. Compute the TRUE authorable denominator. Check for fake zeros (unit compiles, symbol mismatch).

## Method (commands run)
All DB reads via `sqlite3 'file:decomp.db?mode=ro'`. report.json parsed with streamed python3. Spot-checks via `mcp__orchestrator__run_objdiff`, `grep`, `ls` over `src/`.

Key queries:
- Band histogram: `SELECT CASE ... current_percent ... GROUP BY band`
- NULL vs 0 split, `excluded`/`is_stub`/`exclusion_reason` group-bys on `current_percent=0 OR current_percent IS NULL`
- Symbol-prefix taxonomy (`fn_%`, `merged_%`, `??_7/??_R/??_9/??_E/??_G/??__E/??__F/??0/??1`)
- Unit-tree rollup (`default/xdk/%` vs `default/lib/binkxenon/%` vs rest)
- `ls src/<unit>.cpp` existence checks; `grep` for stub bodies
- report.json: per-unit `measures.matched_code==0 && total_code>0` rollup
- `run_objdiff merged_8268BAA8` → confirmed ICF-artifact error path

## Findings

### F1 — The scout number is a category error: "0%" = 1,537 explicit-zero + 18,089 NULL
`SELECT COUNT(*),SUM(size) WHERE current_percent=0` → **1,537 rows / 277,572 bytes**.
`WHERE current_percent IS NULL` → **18,089 rows / 5,161,228 bytes**.
Together: 19,626 / 5,438,800 — matching the scout's "0%" figure exactly. So 92% of the "zero bucket" is `NULL` (never scored), not a measured 0%. Treating them identically for this census; both mean "no match recorded." (load-bearing: the roadmap must not read 5.44 MB as "failing decomp" — it is overwhelmingly unscored non-game code.)

### F2 — 86% of the bucket is `excluded=1` (16,950 rows / 5,126,696 bytes)
`SELECT excluded,COUNT(*),SUM(size) ... GROUP BY excluded` → excluded=1: 16,950 / 5,126,696; excluded=0: 2,676 / 312,104. The scout never mentioned `excluded`. **Only 312 KB of the 5.44 MB is non-excluded.**

`exclusion_reason` is mostly NULL text (stale, like `verdict_reason`): 15,765 rows have `(none)`, 979 "XDK/SDK runtime library", 203 "Third-party library", 3 "Linker glue". The *reason* text is unreliable, but the `excluded` flag tracks the unit tree (see F3).

### F3 — The entire bucket lives under two non-authorable trees: `xdk/` and `binkxenon/`
Unit-tree rollup of all zero/null:
| tree | rows | bytes | authorable? |
|---|---|---|---|
| `default/xdk/*` | 16,782 | 5,043,264 | NO — Xbox Dev Kit (D3D9/D3DX9, XAudio2, NUI/Kinect speech, xgraphics shader compiler). No `src/*.cpp` exists for any (`ls src/xdk/... ` → NO SRC ×5/5). |
| `default/lib/binkxenon/*` | 187 | 86,428 | NO — RAD Game Tools Bink video SDK; 17 units, zero have a `src/*.cpp` (`ls` → all NOCPP). |
| everything else | 2,657 | 309,108 | mixed (see F4–F6) |

Every zero/null unit is prefixed `default/` (none use the `src/` unit prefix). XDK alone is **43.5% of the entire binary's `total_code`** (4,951,700 / 11,379,348 from report.json per-unit sum); Bink is 0.7%. **44.2% of the 11.38 MB binary is third-party/SDK code with no source to author.**

### F4 — Final category table (the deliverable)
Scope = all zero/null rows (19,626 / 5,438,800).
| category | count | bytes | authorable? | route |
|---|---|---|---|---|
| (a) XDK/SDK units (no src) | 16,782 | 5,043,264 | NO | exclude-from-denominator |
| (b) Bink video SDK units (no src) | 187 | 86,428 | NO (3rd-party) | exclude-from-denominator (or port from RAD if ever needed) |
| (d) merged_/ICF artifacts (non-xdk/bink) | 1,903 | 161,956 | NO — not real functions | exclude (use `lookup_merged_symbol`) |
| (a') EH funclets `fn_<addr>` (non-xdk/bink) | 34 | 2,512 | NO — MSVC EH, not source-authorable | tooling fix (byte-pair like the 1,328 already at 100%) |
| (f) boilerplate `??_/??__` (vftable/RTTI/thunk/deleting-dtor/dyninit/atexit) | 313 | 28,156 | NO — compiler-generated | exclude (generated by ctor/class decl) |
| (c+g) authorable plain functions (unit has src cpp) | 407 | 116,484 | YES (377 are `is_stub=1`) | write fresh / port from og-dc3 / replaced-by-native |

Verified the merged_ classification: `run_objdiff merged_8268BAA8` returns *"is a linker ICF artifact (merged symbol), not a real function. Use lookup_merged_symbol"* — these 1,903 are not authorable and must be removed from any denominator. There are 2,657 merged_ NULL rows DB-wide across 791 distinct units; only 90 merged_ rows are at 100%.

### F5 — EH funclet pairing DID reach the DB (memory `reference_objdiff_funclet_pairing` confirmed)
`fn_%` by band DB-wide: **1,328 at 100%**, 232 NULL, 25 partial, 1 at 0%. So objdiff v4.2.0's byte-signature funclet pairing landed in report.json→decomp.db; the +1,264 matched claim is reflected. Only 232 funclets remain unpaired (34 of them in the non-xdk/bink slice, 17,184 bytes total across the whole 0% bucket including xdk). These are not source-authorable; closing them is a tooling job, not a decomp job.

### F6 — The 407 authorable functions are Xbox-platform backends + native-stubbed game code
Subsystem rollup of the 407:
- **synth_xbox (XAudio2 audio backend): 223 fns / 60,460 bytes** — `Synth360`, `Mic360`, `FxSend360`, `FxSendReverb360`, `fft_altivec`, etc. The native port uses miniaudio/FFmpeg, so these are Xbox-only.
- **rnddx9 (D3D9 renderer): 72 fns / 26,672 bytes** — `DxTex::SyncBitmap`, `DxMesh`, `Rnd_Xbox`. Native uses WebGPU.
- **os (platform): 43 fns / 13,572 bytes** — `PlatformMgr::Poll` (4,844 B), `JoypadPollCommon`, Joypad_Xbox.
- **gesture/kinect: 9 / 6,956** — `DepthBuffer3D::DrawShowing` (5,188 B target) is in `src/.../DepthBuffer3D.cpp:184` but its native body is `// Kinect depth rendering not available on native` → real native stub, NOT a fake zero, is_stub=1, 0%.
- other-game 40 / 4,516; moviebink 5 / 2,664; net/3rd-party (json-c/curl) 15 / 1,644.

377 of 407 are `is_stub=1` (confirmed `DrawShowing` body is an empty/comment placeholder). The 30 non-stub remainder are almost entirely `default/link_glue` template instantiations (`ObjPtrList<T>::RefOwner/Owner`, 40-96 B each) — generated glue, effectively boilerplate.

### F7 — NO meaningful fake zeros among authorable code
Query: non-excluded, non-stub, zero/null, not link_glue, not merged_, not `??` → **4 rows**, all `lbl_82D4xxxx` in `default/xdk/xgraphics/buildssa|buildcfg` (data labels, not functions). So there is no population of "unit compiles but symbol-mangling drift fakes a zero" in game code. The is_stub flag is reliable here: `DrawShowing` is is_stub=1 with a real placeholder body; the 377 authorable stubs are genuine empty/partial bodies, not mangling artifacts.

### F8 — report.json corroborates: only 15 authorable whole-units are fully unmatched (32 KB)
Per-unit `matched_code==0 && total_code>0`: **1,097 units / 5,050,780 bytes** fully unmatched. Of those **1,065 are xdk (4,940,180 B), 17 are binkxenon (78,568 B), and only 15 are authorable (32,032 B)**: synth_xbox DSP units (SpectralAnalysis, FFT 10,736 B, EnvelopeGenerator, GranularSynth, PeakDetector, GainEffect, FilterCoeffs, FxSendPitchShift, HeadsetPlaybackEffect), midi/DisplayEvents, net/curl/http_proxy, oggvorbis/VorbisMem, two license stubs (TomCrypt/Zlib, 24 B each), and link_glue (6,372 B). This is the only "whole units never decompiled" list that matters.

### F9 — The TRUE denominator
- report.json: total_code **11,379,348**, matched_code **4,983,704** = **43.8%** (the headline).
- XDK + Bink = 4,951,700 + 78,568 = **5,030,268 (44.2%)** is non-authorable.
- **Authorable code = 6,349,080 bytes.** Matched 4,983,704 of that = **78.5% of authorable code already matches.**
- Remaining authorable work in the zero bucket = the **407 functions / 116,484 bytes** (F6), and of those the genuinely game-relevant (non-synth_xbox, non-rnddx9 Xbox-backend, non-link-glue) is roughly **~100 fns / ~25 KB** (os + gesture + moviebink + other-game). The synth_xbox/rnddx9 ~283 fns / ~87 KB are Xbox HW backends the native port replaces — author them only for binary-matching completeness, not for the native port.

### F10 — DB has 4,091 more rows than report.json (52,504 vs 48,413)
DB `excluded=0`: 33,548; `excluded=1`: 18,956. report.json total_functions = 48,413. The ~4,091 surplus is DB rows for symbols that report.json doesn't count as functions (data labels `lbl_`, some link_glue, RTTI). Two separate planes (consistent with `reference_objdiff_funclet_pairing` memory: report.json vs decomp.db are distinct). Use report.json for the denominator; the DB over-counts by including data/label rows.

## Implications for the roadmap
1. **Re-baseline the headline.** 43.8% is "% of the whole XEX including the XDK we will never write." The honest, decision-useful number is **78.5% of authorable code matched**. Define "done" against the 6.35 MB authorable denominator, not 11.38 MB. This single reframing changes how close the project looks (78.5% vs 43.8%).
2. **The 5.44 MB zero bucket is NOT remaining work.** 5.13 MB is XDK+Bink+ICF+boilerplate (non-authorable). Real remaining work *in this bucket* is 407 fns / 116 KB, and the game-relevant slice is ~100 fns / ~25 KB.
3. **Stop counting XDK in progress metrics** — exclude `default/xdk/*` and `default/lib/binkxenon/*` from the matched% denominator (a one-line filter in `measure_progress.sh` / `sync_match_percent.py`'s reporting view). Without this, every progress report is diluted 44% by un-writable code.
4. **synth_xbox + rnddx9 (283 fns / 87 KB) are matching-only targets** — they don't help the native port (which uses miniaudio/WebGPU). Prioritize them last, or explicitly mark them "binary-match-only" so native-port effort isn't spent here.
5. **The ~100 game-relevant authorable stubs** (os/PlatformMgr, gesture/DepthBuffer3D, moviebink, json-c, midi) ARE the workable frontier in the zero bucket — these are is_stub native placeholders. Several (DepthBuffer3D) are Xbox/Kinect features stubbed for native; matching them needs the original logic ported (route: og-dc3 or write fresh against asm).
6. **Funclet tail (232 unpaired `fn_`)** is a tooling job for jeff/objdiff byte-signature pairing, not decomp.

## Tooling gaps found
- **`exclusion_reason` is stale/NULL** (15,765 of 16,950 excluded rows say `(none)`), like `verdict_reason`. The `excluded` flag itself is trustworthy and tracks the unit tree, but the reason text can't be cited. Fix: backfill exclusion_reason from unit-tree at sync time.
- **No authorable-denominator metric exists.** `measure_progress.sh` and report.json only emit the 11.38 MB denominator. Need a view that subtracts xdk+bink (and ideally synth_xbox/rnddx9 Xbox-backends) to report "matched% of authorable."
- **DB merged_/lbl_/funclet rows inflate counts.** `query_functions`/DB joins return merged_ and lbl_ rows that aren't real functions; only `run_objdiff` errors them out. A DB column `is_real_function` (excluding merged_/lbl_/fn_/??_ boilerplate) would make census joins one-liners and stop the "5.44 MB to do" miscount.
- **NULL vs 0 conflation.** Anyone reading `current_percent` must remember NULL=unscored, 0=measured-zero. A computed column or doc note would prevent the scout's error from recurring.
