# MakeString ICF Equivalence — objdiff Array-Size Normalization

**Status:** Part 1 complete (2026-03-03). Part 2 (post-build patcher) is future work.

## Problem

`MakeString<char[N], int, char[M]>` template instantiations (generated by `MILO_ASSERT`, `MILO_LOG`, etc.) produce **identical machine code** regardless of N and M because arrays decay to pointers. The original binary's linker ICF-merged all variants to a single address, but our pre-link `.obj` files each reference their own per-file instantiation.

This caused `bl` instruction mismatches (`diff_arg`) in objdiff wherever the array sizes differed — typically from `__FILE__` string length differences between the original build environment and ours.

### Scale

- **2,550+ functions** affected across **546 translation units**
- Each mismatch cost ~1-5 match% per function

### Example

```
Target (orig): bl ??$MakeString@$$BY07$$CBDH$$BY0CD@$$CBD@@...  → MakeString<char[8], int, char[36]>
Base (decomp):  bl ??$MakeString@$$BY07$$CBDH$$BY0BJ@$$CBD@@...  → MakeString<char[8], int, char[26]>
```

Both produce identical code (arrays decay to `const char*`), but different mangled names caused a `diff_arg` mismatch on the `bl`.

## Part 1: objdiff `reloc_eq()` Array-Size Normalization (Done)

### Implementation

**File:** `../objdiff/objdiff-core/src/diff/code.rs`

Added `normalize_mangled_array_sizes()` function that strips array dimension sizes from MSVC mangled names. The function exploits a key property of MSVC name mangling:

- `Y<digit>` = array type (`Y0` = 1D, `Y1` = 2D, etc.)
- `Y<letter>` = calling convention (`YA` = `__cdecl`, etc.)

This distinction lets us safely identify and strip all array dimension sizes from both:
- **Template arguments:** `$$BY0<size>` (e.g., `$$BY07` = char[8])
- **Function parameters:** `AAY0<size>` (e.g., `AAY0CD@` = const char (&)[36])

### MSVC Encoded Size Format

Sizes after `Y<digit>` use MSVC's standard number encoding:
- Single digit `0`-`9` → values 1-10 (no terminator)
- Hex letters `A`-`P`+ terminated by `@` → values > 10

### Changes

1. **New function** `normalize_mangled_array_sizes(name: &str) -> Option<String>`:
   - Returns `None` for non-template symbols (doesn't start with `??$`)
   - Returns `None` if no array types found
   - Returns normalized name with all dimension sizes stripped

2. **Extended `reloc_eq()` `names_match`** with a third fallback:
   ```rust
   let names_match = direct_match || equivalence_table_match || {
       normalize_mangled_array_sizes(&left_name)
           .zip(normalize_mangled_array_sizes(&right_name))
           .is_some_and(|(l, r)| l == r)
   };
   ```

3. **5 unit tests** covering equivalence, non-template rejection, type-difference rejection, identity, and no-array-in-template.

### Impact

| Metric | Before | After | Change |
|--------|--------|-------|--------|
| Fuzzy match | 45.40% | **54.06%** | **+8.66pp** |
| Complete units | 368 | **969** | **+601** |

## MakeString Type Mismatches (PAD vs PBD) — All AT_LIMIT

The 27 remaining MakeString template type mismatches (detected pattern: `MAKESTRING_TEMPLATE_MISMATCH`) are distinct from the array-size normalization above. These involve argument type differences like `char*` (PAD) vs `const char*` (PBD), not array dimension sizes.

Investigation (2026-03-03) confirmed **all 27 are AT_LIMIT** — they come from `Ease()` function assert stripping and other unfixable compiler artifacts. These are not fixable by changing source-level `Symbol→.Str()` conversions or casting arguments.

Some individual MakeString type mismatches within otherwise-workable functions CAN be fixed with `(char*)` casts (e.g., `DirLoader::LoadHeader` casting `mStream->Name()`, `DirLoader::DirLoader` casting `arr->Str(i)`), but the 27 detected-pattern instances are all in functions that have other unfixable issues.

## jeff PAIR Relocation Fix

**Date:** 2026-03-03

The jeff linker had a bug where `IMAGE_REL_PPC_PAIR` relocations (used for `lis`/`addi` pairs that form 32-bit addresses) were not being applied correctly. The fix processes PAIR relocs by combining the upper and lower 16-bit halves and applying them as a single 32-bit relocation.

This fix resolved many `lis`/`addi` address mismatches in the linked binary and was applied alongside the array-size normalization.
