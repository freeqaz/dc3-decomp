# Mogg v0xE Decryption Failure — 2026-03-23

## Problem

Song audio fails to decrypt on native x86_64. Character animations don't play because the beat never advances (audio failure → frozen timing).

## Root Cause Isolated

**Version 0xB moggs (SFX/shell music) decrypt correctly.** They use a hardcoded `gRB1Key` with simple `ctr_start()` — no key derivation.

**Version 0xE moggs (all song audio) fail.** They use the full `setupCypher()` → `GrindArray()` pipeline which derives the AES key via DTA script evaluation with 71 registered `O##` functions.

## Decryption Pipeline

### v0xB (works)
```
CheckHmxHeader → read nonce → ctr_start(gCipher, nonce, gRB1Key, 16, 0, ctrState)
```

### v0xE (fails)
```
CheckHmxHeader
  → read nonce, mMagicA, mMagicB, mKeyMask (via HvDecrypt), mKeyIndex
  → setupCypher(0xE):
      1. KeyChain::getMasher(masterKey)     — LCG(0xEB), 32 bytes
      2. KeyChain::getKey(7, gKey, masterKey) — supershuffle×14 + mash
      3. GrindArray(mMagicA, mMagicB, gKey, 16, 0xE)  ← SUSPECT
         - Builds complex DTA script with O## function references
         - Evaluates it 16 times (once per key byte)
         - Uses hashTo5Bits, hashTo6Bits, getRandomLong, getRandomSequence32A/B
         - All use static global state (seeds, usedUp arrays)
      4. gKey[i] ^= mKeyMask[i]
      5. ctr_start(gCipher, nonce, gKey, 16, 0, ctrState)
  → magicHash generation:
      sprintf("{ha %d 1}", mMagicA) → DTA eval → mMagicHashA
      sprintf("{ha %d 2}", mMagicB) → DTA eval → mMagicHashB
```

## Suspect: GrindArray DTA Evaluation

`GrindArray()` (ByteGrinder.cpp:780) constructs a DTA script like:
```
($foo $bar){O68($ix 0){O64{>{O65 $bar}$ix}{O66{za{O67 $bar $ix}}
  (0{O70 $ix}{O69 $foo{O<N>{O67 $bar $ix}$foo}})
  (1{O70 $ix}{O69 $foo{O<N>{O67 $bar $ix}$foo}})
  ...
  (63{O70 $ix}{O69 $foo{O<N>{O67 $bar $ix}$foo}})
}{O70 $ix}}}$foo
```

Then evaluates it 16 times with different byte inputs. Each `O##` function is one of 71 obfuscation operations (XOR, shift, add, etc.). The function-to-number mapping is generated by `pickOneOf32A/B` using LCG permutations.

**Potential failure modes:**
- `long` parameter to `sprintf "%d"` in `pickOneOf32A/B` (LP64 vs ILP32)
- DTA `Int()` truncation differences (DataNode stores int, but intermediates may differ)
- Static seed state in `getRandomLong`/`getRandomSequence32A/B` left dirty by prior calls
- Integer overflow behavior differences in DTA arithmetic operations

## Beat-Freeze Bug (secondary)

When audio fails, `Game::PostWaitStart()` must set `mRealTime = true` (wall-clock timing) instead of `mRealTime = false` (audio timing). Current uncommitted code already has this fix — confirmed beats advance: `beat=1.86 → 25.80` with `paused=0 realTime=1`.

## Unit Test Results

### `MoggV0xETest.DecodeBoyfriendMogg`
- **Without ByteGrinder::Init()**: DTA functions `ma`, `za`, `ya`, `ha`, `O##` are unregistered → key = all zeros
- **With ByteGrinder::Init()**: DTA functions registered, GrindArray runs, **still fails** → key derivation produces wrong bytes on x86_64
- **MoggDecodeTest.DecodeShellMusic (v0xB)**: PASSES — hardcoded `gRB1Key` works, proving the AES-CTR + Ogg pipeline is correct

### Root Cause Confirmed
The `GrindArray()` DTA script evaluation produces a different AES key on native x86_64 than on Xbox PPC. The DTA functions execute, but intermediate integer arithmetic (LCG seeds, hash mappings, XOR chains) diverge somewhere in the 71 `O##` obfuscation operations.
