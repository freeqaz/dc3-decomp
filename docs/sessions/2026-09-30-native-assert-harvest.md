## Defects fixed on this branch

### 1. `Locale::Init` sized its StringTable one byte short per string — DECOMP DEFECT — `7b95cc5e5`
* **Message:** `WARN Resizing string table (139392) adding High Five to Start!` from `Locale::Init` (Locale.cpp:304), once per boot.
* **Divergence:** the second pass sums the unique strings' lengths for `new StringTable(totalStrLen)`. The image adds the terminator — `build/373307D9/asm/system/utl/Locale.s @827E9D90..827E9DB0`: `subf` (strlen+1) / `subi 1` (strlen) / `add r11, r11, r17` / **`addi r17, r11, 0x1`**. Ours summed bare `strlen()`, so the table ran out ~13.5k bytes early and reallocated.
* **Match:** 98.74866 → 98.928185 canonical (98.29 → 98.71 raw); the missing `addi` row is gone and the 26-row r19↔r20 rotation it caused resolved with it. Whole-binary report.json after a full PPC `ninja`: this is the only function that moved (besides `HamCamShot::SetPreFrame`, which landed on main after the fork).
* **Runtime:** the warning is gone (0 in every run after the fix).

### 2. Song time froze for ~200 s after every song under `DC3_FAST_TIME` — native plumbing — `17c040da0`
* **Symptom:** after gameover, 24,190 frames with a NULL current screen before `perform_endgame_screen` — it looked exactly like an endgame hang. Reproduced on the 2026-09-16 main build (1,372 samples frozen at `realSecs=155.28` before I stopped it), so it predates this branch.
* **Chain:** `game_won_common` runs `{game set_realtime TRUE}` → `LiveInput::SetTimeOffset()`. Under `DC3_FAST_TIME`, `CurrentMs()` reads the synthetic `mFastTimeMs`, but `SetTimeOffset`/`SetPostWaitJumpOffset` subtracted `mTimer`'s REAL split and then zeroed `mFastTimeMs`, so the next `CurrentMs()` jumped back by (real elapsed − song time). Song seconds froze; the outro `HamCamShot` (`win_taye_P1_low_dlg.shot`, kTaskSeconds, 185 frames) could not finish, `shot_over` never cleared `$outro_started`, and `endgame_delay_panel` (`is_loaded {! $outro_started}`) never loaded.
* **After:** gameover → endgame in 541–722 frames. `LiveInput::SetTimeOffset`/`SetPostWaitJumpOffset` 100.0 before and after (HX_NATIVE-only).
* Every headless run through `scripts/dc3-agent-test.sh --headless` (which sets `DC3_FAST_TIME`) had this.

### 3. `GameplayTelemetry` flooded the log with a self-inflicted NOTIFY — native plumbing — `2e90f9eaa`
975 of 1,016 tagged messages in a boot-to-main run were `HamDirector::GetMasterKeys: no master clip anim` — the telemetry sampler calling `GetMasterKeys` every sample outside gameplay. Now it asks only once a world with a clip dir exists. 0 after.

### 4. `platform_mgr` stub did not answer `poll_xsocial_capabilities` — native plumbing — `032fd8c0c`
`perform_final_results_panel` polls it every frame; unhandled, it produced **55,639** of 56,327 tagged messages in one run. Stub now answers 0 (no LIVE social), like its other LIVE queries.

### 5. SIGSEGV leaving a perform song — native plumbing — `f02802984`
```
MILO_WARN: ObjPtrList::ReplaceNode: suppressed erase during ReplaceList (owner=<null>)
Caught SIGSEGV (signal 11) at address 0xf0
  FaderGroup::~FaderGroup (Faders.cpp:261)  <- popped a NULL Fader, called RemoveClient
  StandardStream::~StandardStream <- MoggClip::~MoggClip <- DirUnloader::PollLoading
DC3_EXIT: how=fatal_signal detail=SIGSEGV code=139
```
Every perform song → `perform_complete` → continue crashed here. Native `Hmx::Object::ReplaceRefs` walks a snapshot of the ring but raises `gInReplaceList`, and `ObjPtrList::ReplaceNode` suppressed its erase whenever that flag was up — leaving a NULL in a `kObjListNoNull` list. The suppression exists for the LIVE ring walk; in the snapshot walk nothing points into a list's node chain, so a new `gInRefSnapshot` flag lets `ObjPtrList` erase there exactly as the image does. `ObjPtrVec` keeps its suppression on purpose (vector erase shifts nodes the snapshot still points at). After: the route reaches `song_select_screen`, no signal, the warning count 2 → 0. HX_NATIVE-only; whole-binary PPC report unchanged.

Not adjudicated; no decompiled-function divergence found.

## Tooling defects found (documented, not fixed)

1. **`POST /api/input/press` is dead in dc3-native.** It answers `{"ok":true}`, but the linked `Joypad_Native.cpp` is milo-native-engine's, compiled into `libmilo-engine.a` **without** `DC3_HTTP_SERVER`, so `newButtons |= TheHttpServer->ConsumeHttpButtons()` is compiled out (`nm`: `HttpServer::ConsumeHttpButtons` is defined and never called; dc3's own `native/src/platform/Joypad_Native.cpp` is not in any target). Measured: zero effect on `main_screen` and results screens, immediate or delayed. `docs/tools/HTTP_DEBUG_SERVER.md`'s "HTTP-only navigation" workflow cannot work. The fix belongs in the engine repo (a consumer-supplied input hook); the harvest drives menus through `MILO_INPUT_SCRIPT` instead.
2. **`DC3_FAST_BOOT` skips the title screen's DTA.** `UIManager::Poll`'s HX_NATIVE boot-advance table jumps `title_screen → wait_main_after_saveload_screen` after 10 frames without `title_panel`'s `NAV_SELECT_MSG`, so `$post_load_dest_screen` is never set (two spurious `title.dta` messages: `DataNodes 0 and main_screen … not compatible`, `Data 0 is not String`). Confirming the title for real (the harvest's route does) removes both.

## Instrument lessons (so the next harvest does not repeat them)

* **Never probe with `/api/dta/eval` during a harvest.** My hand probes produced four FAILs (`Couldn't find 'units'`, a PropSync assert, two `not function or object`) and an `unhandled msg: focus_component` that read exactly like game messages. The harvester uses only screen/frame/telemetry/screenshot.
* **Bound gameplay on beat progress, not wall clock.** Under `DC3_FAST_TIME` song time is per-frame; box load (load average 46–91 from other lanes) moved the frame rate ~10×.
* **Pin the binary per run.** Relinking `dc3-native` mid-run made addr2line attribute every site of that run (`h11`) to `Debug::Modal`/`MakeString`; the harvester now hard-links the executable into its `--out` dir.
* **`pkill -f` with a pattern that also appears later in the same command line kills your own shell** (did it twice). Kill by PID from the env (`DC3_HTTP_PORT`) instead.
