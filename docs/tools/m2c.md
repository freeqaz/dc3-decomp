# m2c - Machine Code to C Decompiler

m2c is a decompiler that converts assembly code into C source code. It's designed specifically for decompilation projects that aim to produce matching assembly when compiled.

**Repository:** `~/code/milohax/m2c`
**Online version:** https://simonsoftware.se/other/m2c.html

## Installation

m2c is pure Python and requires no compilation:

```bash
# Ensure Python 3.8+ is available
python3 --version

# Install optional graphviz for control flow visualization
pip install graphviz --user  # or: pipx install graphviz

# Test the installation
cd ~/code/milohax/m2c
python3 m2c.py --help
```

## Basic Usage

```bash
# General syntax
python3 ~/code/milohax/m2c/m2c.py [options] [-t <target>] [--context <file>] [-f <function>] <asmfile>

# For DC3 (Xbox 360 / PowerPC / CodeWarrior / C++)
python3 ~/code/milohax/m2c/m2c.py -t ppc-mwcc-c++ input.s

# Decompile specific function
python3 ~/code/milohax/m2c/m2c.py -t ppc -f "MyFunction" input.s

# With context file for types
python3 ~/code/milohax/m2c/m2c.py -t ppc --context types.h input.s
```

## Target Specifications

For DC3, use one of these targets:

| Target | Description |
|--------|-------------|
| `ppc` | PowerPC with MWCC and C++ (alias for `ppc-mwcc-c++`) |
| `ppc-mwcc-c++` | Explicit PowerPC MWCC C++ |
| `ppc-mwcc-c` | PowerPC MWCC C |

## Key Options

### Input/Output
```bash
--context FILE     # Read types/structs from a preprocessed C file
-f, --function FN  # Decompile specific function (name or index)
--globals MODE     # "all", "used" (default), or "none"
--stack-structs    # Output stack variable templates
```

### Code Style
```bash
--valid-syntax     # Emit compilable C (uses macros for unknowns)
--allman           # Allman brace style
--pointer-style X  # "left" (int* x) or "right" (int *x, default)
--no-casts         # Omit type casts
```

### Analysis
```bash
--void             # Assume function returns void
--gotos-only       # Use gotos instead of reconstructed loops
--no-switches      # Disable switch detection
--debug            # Print debug info inline
--print-assembly   # Print assembly alongside C output
--visualize        # Generate SVG control flow graph
```

## DC3 Assembly Format Conversion

DC3's assembly (generated by decomp-toolkit) uses a custom format that m2c doesn't directly understand. To use m2c with DC3, you need to convert the assembly format.

### DC3 Format (dtk)
```asm
.fn "?MyFunc@MyClass@@QAAHXZ", global
/* 823D0E40 003C5840  7D 88 02 A6 */  mflr r12
/* 823D0E44 003C5844  48 5C CA E9 */  bl __savegprlr_29
...
.endfn "?MyFunc@MyClass@@QAAHXZ"
```

### m2c Expected Format
```asm
.global MyClass_MyFunc
MyClass_MyFunc:
mflr r12
bl __savegprlr_29
...
blr
```

### Conversion Script

Create `tools/asm_to_m2c.py`:

```python
#!/usr/bin/env python3
"""Convert DC3 dtk assembly to m2c-compatible format."""

import re
import sys

def demangle_simple(name):
    """Simple MSVC demangling for readability."""
    # Remove ?/?? prefixes and @@ suffixes
    name = re.sub(r'^\?\??\d*', '', name)
    name = re.sub(r'@@.*$', '', name)
    # Replace @ with _
    name = name.replace('@', '_')
    return name or 'unknown'

def convert_asm(input_text):
    """Convert dtk assembly to m2c format."""
    lines = input_text.split('\n')
    output = []
    in_function = False

    for line in lines:
        # Function start
        fn_match = re.match(r'\.fn\s+"([^"]+)"', line)
        if fn_match:
            mangled = fn_match.group(1)
            demangled = demangle_simple(mangled)
            output.append(f'.global {demangled}')
            output.append(f'{demangled}:')
            in_function = True
            continue

        # Function end
        if line.startswith('.endfn'):
            in_function = False
            continue

        # Skip labels we don't need
        if line.startswith('.L_'):
            label = line.rstrip(':')
            output.append(f'{label}:')
            continue

        # Instruction lines (strip hex comments)
        instr_match = re.match(r'/\*[^*]+\*/\s+(.+)$', line)
        if instr_match and in_function:
            output.append(instr_match.group(1))
            continue

        # Skip other directives
        if line.startswith('.') or line.startswith('#'):
            continue

    return '\n'.join(output)

if __name__ == '__main__':
    if len(sys.argv) < 2:
        print("Usage: asm_to_m2c.py <input.s> [function_name]")
        sys.exit(1)

    with open(sys.argv[1]) as f:
        content = f.read()

    print(convert_asm(content))
```

## Context Files

Context files provide type information to improve decompilation quality:

```c
// context.h
typedef unsigned int u32;
typedef int s32;
typedef float f32;

struct Vector3 {
    f32 x, y, z;
};

class CharClip {
public:
    void* mData;
    int mFlags;
    float mLength;

    int AllocSize();
    void SetFlags(int);
};

// Function signatures
int CharClip_AllocSize(CharClip* this);
```

Preprocess with:
```bash
cpp -P context.h > context_processed.h
python3 ~/code/milohax/m2c/m2c.py -t ppc --context context_processed.h input.s
```

## Stack Variable Templates

Use `--stack-structs` to get templates for local variables:

```bash
python3 ~/code/milohax/m2c/m2c.py -t ppc --stack-structs input.s
```

Output includes:
```c
struct _m2c_stack_MyFunc {
    /* 0x00 */ char pad0[0x10];
    /* 0x10 */ s32 var1;
    /* 0x14 */ s32 var2;
};
```

Add this to your context file to name stack variables.

## Workflow Integration

### Typical Decompilation Workflow

1. **Identify target function** via objdiff:
   ```bash
   objdiff-cli report query build/373307D9/report.json --functions --min-percent 0 --max-percent 50
   ```

2. **Extract and convert assembly**:
   ```bash
   python3 tools/asm_to_m2c.py build/373307D9/asm/path/to/File.s > /tmp/func.s
   ```

3. **Generate initial C code**:
   ```bash
   python3 ~/code/milohax/m2c/m2c.py -t ppc --valid-syntax /tmp/func.s
   ```

4. **Refine with context**:
   ```bash
   python3 ~/code/milohax/m2c/m2c.py -t ppc --context include/types.h /tmp/func.s
   ```

5. **Copy to source, compile, compare**:
   ```bash
   ninja build/373307D9/src/path/to/File.obj
   objdiff-cli diff -p . "MyFunc" -f json --include-instructions
   ```

### Comparison with Manual Approach

| Approach | Pros | Cons |
|----------|------|------|
| **m2c** | Fast initial draft, handles control flow | May need format conversion, output needs cleanup |
| **Manual** | Full control, no tooling issues | Slower, easy to miss patterns |
| **Hybrid** | Best of both | Requires understanding both approaches |

**Recommended:** Use m2c for initial structure, then manually refine for matching.

## Common Issues

### "Unknown instruction"
The assembly may contain pseudo-instructions or macros. Convert them manually or add to m2c's instruction tables.

### Wrong types
Add more context via `--context`. m2c infers types but can be wrong without hints.

### Incorrect control flow
Try `--gotos-only` to get raw control flow, then manually reconstruct loops.

### Mangled C++ names
m2c has built-in CodeWarrior demangling. For MSVC-style names (like DC3), you may need to demangle externally.

## Advanced: Custom Demangling

For DC3's MSVC-mangled symbols, use a demangler:

```bash
# Using undname (Windows) or similar
echo "?MyFunc@MyClass@@QAAHXZ" | undname
# Output: public: int __cdecl MyClass::MyFunc(void)
```

Or use Python's `demumble` or write custom demangling based on MSVC scheme.
