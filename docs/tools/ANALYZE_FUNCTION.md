# analyze-function

Combined objdiff + Ghidra MCP analysis tool for agent-driven decompilation workflows.

## Overview

`analyze-function` provides a unified view of function analysis by combining:
- **objdiff**: Match percentage, verdict, detected patterns, suggestions
- **Ghidra**: Decompiled pseudo-C, cross-references (callers and callees)

This eliminates context-switching between tools and provides all relevant information in one output.

## Usage

```bash
# Default markdown output
./bin/analyze-function "Game::PollShuttle"

# JSON output (for programmatic access)
./bin/analyze-function "Game::PollShuttle" -f json

# Skip cross-references (faster)
./bin/analyze-function "Game::PollShuttle" --no-xrefs

# Suppress Ghidra connection warnings
./bin/analyze-function "Game::PollShuttle" -q

# Verbose mode for debugging symbol resolution
./bin/analyze-function "Game::PollShuttle" -v

# Disambiguate with unit name
./bin/analyze-function "Object::Load" -u obj/Data

# Save to file
./bin/analyze-function "Game::PollShuttle" -o analysis.md
```

## Options

| Option | Description |
|--------|-------------|
| `-f, --format` | Output format: `markdown` (default), `json` |
| `-p, --project` | Project directory (default: current directory) |
| `--no-xrefs` | Skip cross-reference lookup |
| `-o, --output` | Output file (default: stdout) |
| `-v, --verbose` | Print detailed symbol resolution info for debugging |
| `-q, --quiet` | Suppress Ghidra connection warnings |
| `-u, --unit` | Specify compilation unit to disambiguate duplicate symbols |

## Function Name Resolution

The tool automatically resolves function names for Ghidra:

1. **Demangled names** work: `Game::PollShuttle`, `RndMat::Copy`
2. **Mangled names** work: `?PollShuttle@Game@@AAAMXZ`
3. **Partial names** search: If exact match fails, searches Ghidra symbols

When ambiguous, the tool shows possible matches and fails gracefully.

### Destructor Filtering

The tool automatically filters out `::dynamic atexit destructor` symbols that are generated by the compiler for static local variables. This prevents ambiguity errors when a function has static locals, which would otherwise produce multiple symbol matches.

### Address Verification

When resolving symbols, the tool verifies Ghidra's resolved address against the expected address from `symbols.txt`:
- If addresses match, decompilation proceeds normally
- If addresses mismatch, a warning is shown and the expected address is used for decompilation
- This catches cases where Ghidra resolves to a wrong function with a similar name

## New Capabilities

### Callee Extraction

Cross references now show both directions:
- **Called by**: Functions that call this function (callers/inbound references)
- **Calls**: Functions that this function calls (callees/outbound references)

### Stub Detection

Automatically warns when Ghidra returns a stub function instead of the real implementation:
- Detects `__savegprlr` prologue-only stubs
- Warns on size mismatch (few lines of code for a large function)
- Shows "Resolution Warnings" section with recommendations

Common stub indicators:
- Decompilation has only a few body lines but objdiff reports hundreds of bytes
- Only a return statement but significant function size
- Contains `__savegprlr` prologue with minimal body

## Requirements

- **objdiff-cli**: Extended version at `./bin/objdiff-cli`
- **Ghidra MCP**: Running at `http://127.0.0.1:8000/mcp/v1` (FastMCP/Uvicorn service)
- **Python 3**: With `requests` library

### Service Startup

Start the Ghidra MCP service before using analyze-function:

```bash
# Start the service (FastMCP on port 8000)
./tools/ghidra/pyghidra-service.sh start

# Check if running
./tools/ghidra/pyghidra-service.sh status

# View logs if issues occur
./tools/ghidra/pyghidra-service.sh logs
```

The service takes 5-10 seconds to fully initialize. Wait for "Uvicorn running on http://127.0.0.1:8000" in the logs.

### XEX Binary Support

The service now works directly with XEX files (Xbox 360 executables). Ghidra's XEX loader automatically handles:
- PowerPC big-endian code
- XEX compression and encryption
- Section mapping and relocation
- Symbol table extraction

No pre-processing or ELF conversion is needed.

## How It Works

1. Runs `objdiff diff --verdict` to get match analysis
2. Extracts the function symbol from objdiff output
3. Searches Ghidra for the function (by mangled name pattern)
4. Filters out destructor symbols to avoid ambiguity
5. Looks up expected address from `symbols.txt`
6. Verifies resolved address matches expected address
7. Decompiles using the verified address (more reliable than name)
8. Detects potential stubs or wrong functions
9. Fetches cross-references (callers and callees)
10. Combines all data into unified output

## Gradual Information Approach

By default, the tool includes:
- **Decompilation**: Always (essential for understanding the target)
- **Cross-references**: By default (lightweight, provides context)
- **Call graph**: On request (heavier, shown as command hint)

Use `--no-xrefs` for faster output when cross-references aren't needed.

## Integration with Workflows

### Agent Usage

Agents can request analysis and parse the output:

```bash
# Get analysis as markdown for reasoning
ANALYSIS=$(./bin/analyze-function "MyFunc")

# Get structured data for programmatic use
./bin/analyze-function "MyFunc" -f json | jq '.objdiff.verdict.classification'

# Use verbose mode to debug resolution issues
./bin/analyze-function "MyFunc" -v 2>&1 | head -20
```

### Batch Analysis

Combined with objdiff's query capabilities:

```bash
# Find near-matches and analyze each
./bin/objdiff-cli report query build/373307D9/report.json --functions \
  --min-percent 90 --max-percent 99 --limit 10 -f json | \
  jq -r '.results[].name' | \
  while read func; do
    ./bin/analyze-function "$func" >> batch_analysis.md
  done
```

## Troubleshooting

### Service Connection Issues

#### "Could not connect to Ghidra MCP server"

The Ghidra MCP service must be running. Common fixes:

```bash
# Check if service is running
./tools/ghidra/pyghidra-service.sh status

# Start service if not running
./tools/ghidra/pyghidra-service.sh start

# View logs to diagnose startup issues
./tools/ghidra/pyghidra-service.sh logs
```

Use `-q` flag to suppress Ghidra connection warnings if Ghidra analysis is not needed.

#### Service startup failures

Common causes:
- **Port 8000 already in use**: Check `lsof -i :8000` and kill conflicting process
- **Java not found**: Verify `JAVA_HOME` points to JDK 17+ (set in pyghidra-service.sh)
- **Ghidra install missing**: Check `GHIDRA_INSTALL_DIR` path in service script
- **Project locks**: Service clears stale `.lock` files on startup automatically
- **ChromaDB issues**: Delete `/tmp/claude/ghidra_user/chroma_db/` to rebuild index

Check the log file at `/tmp/claude/pyghidra-mcp-dc3.log` for detailed error messages.

#### Wrong port or endpoint

The new FastMCP service uses:
- Port: `8000` (changed from old `8765`)
- Endpoint: `/mcp/v1` (changed from old `/mcp`)
- Full URL: `http://127.0.0.1:8000/mcp/v1`

If you have an old `.mcp.json` or hardcoded URLs, update them to the new endpoint.

### Function Resolution Issues

#### "Ambiguous function name"
Multiple functions match your query. Use a more specific name, include the class name, or use `--unit` to specify the compilation unit.

#### Empty decompilation
Ghidra may not be able to fully analyze some functions (virtual methods, compiler-generated code). The raw bytes are still available via `read_bytes` MCP tool.

#### No cross-references
Some functions have no callers or callees. This is normal for entry points or leaf functions.

#### Resolution Warnings appear
If you see stub detection warnings, verify the function was resolved correctly:
1. Check the address in the output against your symbols
2. Try using the mangled name directly
3. Use `-v` to see the resolution process
4. Consider using the address directly: `./bin/analyze-function "0x826CC098"`

#### Address mismatch warning
This means Ghidra resolved to a different address than expected. The tool automatically uses the expected address from `symbols.txt` for decompilation, but you should verify the symbol mapping is correct.

### XEX Binary Issues

If Ghidra fails to load the XEX file:
- Verify XEX path in service script points to valid file
- Ensure Ghidra has XEX loader extension installed
- Check Ghidra logs for loader errors
- Verify binary is valid Xbox 360 XEX format (not corrupted)
