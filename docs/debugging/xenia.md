# Xenia Emulator — DC3 Debug & Decomp Testing

Run the original DC3 debug XEX (or decomp XEX) under Xenia on Linux with Vulkan GPU rendering, NUI/Kinect stubs, and frame capture.

## Quick Reference

```bash
XENIA=/home/free/code/milohax/xenia
XENIA_BIN=$XENIA/build/bin/Linux/Checked/xenia-headless

# Boot the original debug XEX with Vulkan rendering
$XENIA_BIN \
  --target=./orig-assets/debug.xex \
  --gpu=vulkan \
  --dc3_nui_patch_layout=original \
  --dc3_crt_skip_nui=true \
  --headless_timeout_ms=30000

# Boot the decomp XEX
$XENIA_BIN \
  --target=./build/373307D9/default.xex \
  --gpu=vulkan \
  --dc3_nui_patch_layout=auto \
  --dc3_crt_skip_nui=true \
  --headless_timeout_ms=30000

# Headless (no GPU) — faster, for testing boot progression only
$XENIA_BIN \
  --target=./orig-assets/debug.xex \
  --dc3_nui_patch_layout=original \
  --dc3_crt_skip_nui=true \
  --headless_timeout_ms=15000
```

**Important**: The Vulkan branch must be checked out — `headless-vulkan-linux`, not `master`. The `master` branch builds a NullGPU-only binary.

## Prerequisites

- Xenia fork at `../xenia` (relative to dc3-decomp root)
- Branch: `headless-vulkan-linux`
- Vulkan ICD installed (tested with NVIDIA RTX 3090, driver 590.x)
- **Sandbox**: Must use `dangerouslyDisableSandbox: true` for GPU access

## Building

```bash
cd /home/free/code/milohax/xenia
git checkout headless-vulkan-linux
make -C build -f Makefile xenia-headless -j$(nproc)
```

Binary lands at `build/bin/Linux/Checked/xenia-headless` (~200 MB).

## Core CLI Flags

### GPU & Rendering

| Flag | Default | Description |
|------|---------|-------------|
| `--gpu=<backend>` | `null` | `null` (no rendering) or `vulkan` |
| `--dump_frames_path=<path>` | (empty) | Dump frames as PPM files to this directory |
| `--headless_capture_interval=N` | `100` | Capture every Nth frame swap (0 = every frame) |
| `--vsync=<bool>` | `true` | Enable vsync |
| `--dump_shaders=<path>` | (empty) | Dump compiled GPU shaders |

### Execution Control

| Flag | Default | Description |
|------|---------|-------------|
| `--target=<path>` | **(required)** | XEX or ISO to launch |
| `--headless_timeout_ms=N` | `0` | Exit after N ms (0 = run forever) |
| `--headless_report_boot` | `true` | Log boot milestones |
| `--scripted_input="..."` | (empty) | Timed button presses, e.g. `5s:A,7s:START` |
| `--scripted_input_file=<path>` | (empty) | Screen-aware input script (see "Entering Gameplay") |

### DC3 Layout Detection

The hack pack auto-detects whether you're running the original or decomp XEX via .text section fingerprinting.

| Flag | Default | Description |
|------|---------|-------------|
| `--dc3_nui_patch_layout=<mode>` | `auto` | `auto`, `original`, or `decomp` |
| `--dc3_crt_skip_nui=<bool>` | `true` | Nullify NUI/Kinect CRT constructors |

- Use `original` for `debug.xex` / `default.xex` from `orig-assets/`
- Use `auto` or `decomp` for the decomp build XEX
- `auto` uses FNV1a64 fingerprint matching + zero-padding heuristic

### DC3 CRT Constructor Control

The decomp XEX has CRT constructor table issues from `/FORCE` linking. These flags help diagnose which constructors crash.

| Flag | Default | Description |
|------|---------|-------------|
| `--dc3_crt_bisect_max=N` | `-1` | Only run CRT constructors 0..N (-1 = all) |
| `--dc3_crt_skip_indices="..."` | (empty) | Skip specific indices, e.g. `69,75,98-340` |
| `--dc3_crt_skip_nui=<bool>` | `true` | Auto-skip known NUI constructor indices |

### DC3 Debug Overrides

| Flag | Default | Description |
|------|---------|-------------|
| `--dc3_null_read_cache_stream` | `false` | Force ReadCacheStream to return nullptr |
| `--dc3_debug_mempool_alloc_probe` | `false` | Log MemOrPoolAlloc calls with caller info |
| `--dc3_debug_findarray_override_mode` | `off` | DataArray::FindArray override: `off`, `log_only`, `stub_on_fail`, `setupfont_fix` |
| `--fake_kinect_data` | `false` | Inject synthetic Kinect skeleton T-pose data |

### GDB Remote Debugging

```bash
# Terminal 1: start xenia with RSP stub
$XENIA_BIN --target=./orig-assets/debug.xex --gpu=null \
  --dc3_gdb_rsp_stub=true --dc3_gdb_rsp_port=9001 &

# Terminal 2: attach GDB
powerpc-none-eabi-gdb
(gdb) target remote 127.0.0.1:9001
```

| Flag | Default | Description |
|------|---------|-------------|

| `--dc3_gdb_rsp_host` | `127.0.0.1` | Listen address |
| `--dc3_gdb_rsp_port` | `9001` | Listen port |
| `--dc3_gdb_rsp_prelaunch_sleep_ms` | `0` | Pause before launch for debugger attach |

## Frame Capture

Capture GPU-rendered frames as PPM images:

```bash
mkdir -p /tmp/xenia-frames

$XENIA_BIN \
  --target=./orig-assets/debug.xex \
  --gpu=vulkan \
  --dc3_nui_patch_layout=original \
  --dc3_crt_skip_nui=true \
  --dump_frames_path=/tmp/xenia-frames \
  --headless_capture_interval=100 \
  --headless_timeout_ms=15000

# Convert PPM to PNG
magick /tmp/xenia-frames/frame_0100.ppm /tmp/xenia-frames/frame_0100.png
```

Each captured frame produces two files:
- `frame_NNNN.ppm` — gamma-corrected (sRGB), what you'd see on screen
- `frame_NNNN_raw.ppm` — linear, no gamma correction

## DC3 Hack Pack

The hack pack (`dc3_hack_pack.cc`) applies runtime patches to work around missing subsystems. It is gated on `is_decomp_layout`:

- **Original XEX**: Only NUI/Kinect stubs and XBC overrides are applied
- **Decomp XEX**: Full set of CRT fixes, memory manager replacements, init stubs, StringTable construction, etc.

### Hack Categories

| Category | Description |
|----------|-------------|
| `kCrt` | CRT constructor sanitization, `_ioinit`/`_cinit` injection |
| `kSkeleton` | Fake Kinect skeleton data injection |
| `kDebug` | Debug print/fail redirects, printf formatter stubs |
| `kDecompRuntimeStopgap` | Decomp-specific workarounds (FlowManager, HamSongMgr, SynthSecurity stubs) |
| `kImports` | Import thunk and XDK override registration |

### Address Resolution

Addresses come from the patch manifest (`build/373307D9/xenia_dc3_patch_manifest.json`), generated automatically by `scripts/build/generate_xenia_dc3_patch_manifest.py`. The manifest is fingerprinted — if the decomp binary changes, regenerate it with `ninja` (which reruns the manifest generator).

For the original XEX, addresses are resolved via the symbol map (`config/373307D9/symbols.txt`) and signature scanning.

## Entering Gameplay

Navigate the original debug XEX from boot to a playable song using the screen-aware input system:

```bash
$XENIA_BIN \
  --target=./orig-assets/debug.xex \
  --gpu=vulkan \
  --dc3_nui_patch_layout=original \
  --dc3_crt_skip_nui=true \
  --fake_kinect_data=true \
  --scripted_input_file=scripts/dc3-input-flows/xenia-ymca.txt \
  --dump_frames_path=/tmp/xenia-gameplay \
  --headless_capture_interval=300 \
  --headless_timeout_ms=180000
```

**Required flags**:
- `--fake_kinect_data=true` — enables calibration bypass patches (skeleton data + player assignment)
- `--scripted_input_file=` — screen-aware input script that waits for each screen before pressing buttons
- `--dump_frames_path=` — required for headless frame capture to activate

The input script (`scripts/dc3-input-flows/xenia-ymca.txt`) navigates:
attract → title → main (Dance) → choose_mode (Perform) → song_select (YMCA) → difficulty → multiuser (auto-bypass) → loading → **game_screen**

### Calibration Bypass Patches

When `--fake_kinect_data=true`, emulator.cc applies 7 patches to bypass the Kinect calibration flow:

| # | What | Address | Purpose |
|---|------|---------|---------|
| 1 | NOP `bne` | `0x8290834C` | Remove `IsTrackingAllSkeletons()` guard in `SetPlayerPresent` |
| 2 | Tracking ID force | via NuiSkeleton handler | Write IDs 1/2 to both players continuously |
| 3 | Stub `ChoosePlayerSides` | `0x82909968` | Skip skeleton pointer validation |
| 4 | Stub `SetPlayerSkeletonWarningData` | `0x82907880` | Skip skeleton pointer validation |
| 4b | Replace `SetPlayerSkeletonNavData` | `0x82909340` | Always call `SetPlayerPresent(0/1, true)` |
| 5 | Stub `ShouldWaitForRecovery` | `0x82904CD0` | Prevent recovery wait blocking updates |
| 6 | PPC code cave | `0x825EF4D8` | `MultiUserGesturePanel::Poll` → `GotoScreen("loading_screen")` after 400 frames |

### Screen-Aware Input Scripts

The `--scripted_input_file` flag loads a script from the native port's format:

```
# Wait for a screen, then send buttons with frame-relative timing
wait_screen attract_screen
+10 confirm

wait_screen title_screen
+30 confirm

wait_screen main_screen
+10 confirm          # selects "Dance" (first item after skeleton fix)
```

The NopInputDriver reads `TheUI->mCurrentScreen->mName` from guest memory (`0x82F1A8E0` → offset `0x48` → offset `0x20`) to detect screen transitions.

### EDRAM Rendering Fix

Headless frame capture clears EDRAM and destroys host render targets before each `FlushDeferredDraws()` call to prevent ghosting from stale render target content. Key functions:
- `ClearCache()` — destroys cached VkFramebuffer/VkRenderPass objects
- `ResetState()` → `DestroyAllRenderTargets(false)` — destroys host VkImage/VkImageView objects
- `BeginFrame()` — clears accumulated render target tracking
- `vkCmdFillBuffer` on EDRAM buffer — zeros EDRAM content

### Known Rendering Limitations

- Venue lighting is dark/limited during gameplay (shader translation gaps)
- Debug text overlays visible (debug build feature, not a bug)
- XMA audio not functional (SIGSEGV in `XMAHALAllocateContexts` — non-fatal)

## Current Boot Status (as of 2026-03-30)

**Original debug XEX**: Full gameplay reached — boots through splash, menus, song select, loading, and into `game_screen` with 3D venue rendering. Requires `--fake_kinect_data=true` for calibration bypass.

**Decomp XEX**: Main loop stable. Three stubbed blockers prevent progression:
1. **FlowManager::Poll** — corrupt FlowNode vtable (#1 blocker for screen transitions)
2. **HamSongMgr::Init** — config parsing crash (#2 for song selection)
3. **Synth::InitSecurity** — DRM yylex infinite loop (likely permanent stub)

See `../xenia/docs/dc3-boot/STATUS.md` and `HACK_RETIREMENT_MATRIX.md` for full details.
